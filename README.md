# mdx

Поиск и обзорная карта по корпусу `.md`-заметок. Один бинарник, ноль зависимостей,
только стандартная библиотека Go.

## Сборка

    go build -o mdx .
    GOOS=windows GOARCH=amd64 go build -ldflags="-s -w" -o mdx.exe .
    $env:GOOS="windows"; $env:GOARCH="amd64"; go build -o mdx.exe .

## Использование

    mdx index                        # проиндексировать текущий каталог
    mdx search "AllocateChannelSequence"
    mdx search "гипотезы про состояния" -status rejected
    mdx search "канал" -subsystem net -since 30d -full
    mdx digest -out INDEX.md
    mdx stats

Индекс лежит в `.mdx/index.gob` рядом с корпусом. Переиндексация инкрементальная:
перечитываются только файлы с изменившимся sha256, поэтому `mdx index` можно
вешать на git-хук или на таймер.

## Как устроен поиск

Ранжирование сливает два независимых списка через RRF (reciprocal rank fusion):

1. **BM25** по инвертированному индексу. Токенизатор режет `CamelCase`,
   `snake_case` и границы букв/цифр, поэтому `stReplicatedStateFSM` находится и
   по `replicated`, и по `state`, и по `fsm`. Для русского и английского
   применяется лёгкое отсечение окончаний плюс 6-символьный префиксный ключ.
2. **Буквальный проход** по телам фрагментов для hex-адресов и идентификаторов.
   Он существует ровно затем, чтобы `0xF90410` не утонул среди соседних адресов:
   на таких запросах семантическая близость вредна. Результаты, найденные
   буквально, помечаются в выдаче знаком `=`.

Чанкинг идёт по заголовкам, с отслеживанием код-фенсов — `#`-комментарии внутри
C++ и Python не принимаются за заголовки. Каждый фрагмент несёт полный путь
заголовков, чтобы выдачу можно было перепроверить глазами.

## Frontmatter

Поля из YAML-блока становятся фильтрами. Полезный минимум:

    ---
    title: Репликация состояний актёров
    subsystem: replication
    status: open          # open | rejected | done
    date: 2026-08-20
    offsets: ["0x54"]
    ---

`status: rejected` как отдельное поле, а не абзац в тексте, — это то, что
превращает отвергнутые гипотезы в запрашиваемое множество.

## digest --summarize

По умолчанию `digest` строит карту корпуса из заголовков и лид-абзацев, никуда
не ходя. Флаг `-summarize` отправляет тела заметок в Anthropic API (ключ из
`ANTHROPIC_API_KEY`) и кэширует резюме по хэшу файла. Это единственный сетевой
вызов во всей программе; без флага она полностью офлайновая.
